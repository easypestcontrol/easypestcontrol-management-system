# Deploying PestOps

Three containers — PostgreSQL, the NestJS API, the Next.js web — with nginx on
the host terminating HTTPS. Ubuntu 22.04+, 1 GB RAM is enough to start.

Two shapes work. Pick one before you begin, because it decides your DNS:

| | Where the front end runs | DNS |
|---|---|---|
| **All on the VPS** | the `web` container | `app.` and `api.` both → the VPS |
| **Front end on Vercel** | Vercel | `app.` → Vercel, `api.` → the VPS |

The second costs nothing extra and gets you a CDN, but splits the stack in two.
The first is one machine and one thing to reason about. Both are supported by
the config in this folder; nothing changes but where `app.` points and whether
you run the `web` container.

**Vercel talks to `api.` server-side.** Next's rewrites proxy `/api` from the
Vercel runtime, not the browser — so no CORS, and no key ever reaches a browser.
Set `API_URL=https://api.yourdomain.com` in the Vercel project and that is all.

## Before anything: the secrets rule

Secrets are typed **on the machine that needs them**, once, by you.

They do not travel through a chat window, a ticket, a screenshot or a commit.
A key that has been pasted somewhere it did not need to be is a key to rotate,
not a key to be careful with — git keeps history, chat logs are kept, and a
force-push does not help once a repo has been cloned or indexed.

```bash
cd /opt/pestops/deploy
bash set-secrets.sh          # prompts, generates what it can, writes .env at 0600
```

Where each one lives, and why:

| Secret | Where | Why there |
|---|---|---|
| `DB_PASSWORD`, `JWT_SECRET` | `deploy/.env` on the VPS | Generated by the script. No human should ever read them. |
| R2 account id, bucket, key id, secret | `deploy/.env` on the VPS | The API needs them at boot to reach storage. |
| Ola Maps key | Settings → Integrations, in the app | Rotates without a redeploy. Written in, never read back. |
| Razorpay key id + secret | Settings → Integrations, in the app | Same. |
| Cloudflare analytics token | Credentials → Cloudflare R2 → Edit | Read-only. Feeds the usage figures, nothing else. |

`.gitignore` excludes every `.env`. Check before the first push:

```bash
git status --short | grep -i env      # must print nothing
```

## One-time provisioning

```bash
# as root on a fresh VPS
apt update && apt install -y docker.io docker-compose-v2 nginx certbot python3-certbot-nginx
systemctl enable --now docker
```

## Ship the code

```bash
# from your machine — copy the v2 folder (or git clone if you push it to a repo)
scp -r v2 user@your-vps:/opt/pestops
```

## First start

```bash
cd /opt/pestops/deploy
bash set-secrets.sh             # writes .env — see the secrets rule above

docker compose up -d --build    # builds api + web, starts postgres
docker compose exec api npx prisma db push     # create the tables
docker compose exec api npm run db:seed        # company, branches, team, services

# nginx + HTTPS for both names
cp nginx.conf /etc/nginx/sites-available/pestops
sed -i 's/yourdomain.com/YOUR-REAL-DOMAIN/g' /etc/nginx/sites-available/pestops
ln -s /etc/nginx/sites-available/pestops /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d app.YOUR-REAL-DOMAIN -d api.YOUR-REAL-DOMAIN
```

The database is **UTF8** — the schema and `devdb.mjs` both insist on it. A
WIN1252 cluster cannot store a rupee sign or a single Tamil character, and the
first symptom is a 500 from somewhere unrelated. `scripts/to-utf8.mjs` converts
an existing database if you ever inherit one.

### Front end on Vercel

Skip the `web` container (`docker compose up -d db api`), point `app.` at
Vercel, and set one environment variable in the Vercel project:

```
API_URL = https://api.YOUR-REAL-DOMAIN
```

Root directory `v2/apps/web`, build command `npm run build`. Nothing else.

### First sign-in

`https://app.YOUR-REAL-DOMAIN` as `rajesh@shieldpest.in` / `pestops123`.

**Change every seeded password before anyone else has the URL.** They are in
this repository — Team → each member. Then add the Ola and Razorpay keys in
Settings → Integrations, and the Cloudflare token in Credentials.

### Lock the machine down

The IP is public the moment DNS resolves, and brute-force traffic starts within
the hour.

```bash
# key-only SSH — do this from a session you can still get back into
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl reload ssh

apt install -y fail2ban
ufw allow OpenSSH && ufw allow 'Nginx Full' && ufw --force enable
```

Only 22, 80 and 443 should be open. Postgres (5432) and the API (4000) are
bound to loopback in `docker-compose.yml` and must stay that way — nginx holds
the certificate and is the only thing that should be reachable.

## Updates

```bash
cd /opt/pestops && git pull        # or scp the changed files
cd deploy && docker compose up -d --build
docker compose exec api npx prisma db push   # if the schema changed
```

## Backups

The database lives in the `pgdata` volume:

```bash
docker compose exec db pg_dump -U pestops pestops | gzip > /root/pestops-$(date +%F).sql.gz
```

Put that line in a cron job and copy the files off the machine. A backup that
has never been restored is a hope, not a backup — restore one into a scratch
database before you need to.

## If a key leaks

Rotate it. Do not scrub, do not force-push, do not hope.

| Leaked | Rotate at |
|---|---|
| R2 access key / secret | Cloudflare → R2 → Manage API Tokens → roll |
| Cloudflare API token | Cloudflare → My Profile → API Tokens |
| Ola key or client secret | Ola Krutrim console → project → regenerate |
| Razorpay keys | Razorpay dashboard → Settings → API Keys |
| `JWT_SECRET` | re-run `set-secrets.sh`, restart — every session is invalidated |
| VPS root | new SSH key, `PermitRootLogin prohibit-password`, fail2ban |

Then check what the key could reach while it was live: R2 object listings,
Razorpay transactions, Ola usage.
